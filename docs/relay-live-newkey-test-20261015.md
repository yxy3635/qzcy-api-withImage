## 方法与实际边界

- 每条请求只有一个新的用户输入、独立 UUID 标记，不带历史会话、`previous_response_id` 或共享 response_id；每组并发请求经 barrier 同时发起。
- 请求为 `stream:true`、`store:false`，输出上限 4096 tokens。测试提示要求标准库 Python 日志统计示例和简短中文解释，属于较短的新对话输入。
- SSE 按事件解析，空 delta/注释心跳不算真实文本；必须出现 `response.completed` 才判成功。达到 360 秒测试上限会明确标记为测试截止，而不是服务器主动断开。
- 直接调用 HTTP API，没有启动三个真实 Codex/编辑器进程。因此没有覆盖实际客户端自动附加的大量文件、工具描述、长历史、客户端取消、连接池或超时策略。
- 客户端到网站使用 HTTP/1.1，不能据此得知后端到上游协商的是 HTTP/1.1 还是 HTTP/2。未读取本批服务器后端日志或供应商 ID，不能证明与此前失败用户走了相同供应商，不能认定尚未确认部署的 v2 已解决故障。
- gzip 组采用真实 gzip 请求体；未进行线上 zstd 测试。此前 gzip/zstd/混合格式的本地 6 流并发回归属于另一层验证。
- xhigh 首段文本用时约 39–55 秒，此处最终均完成。说明短时间只有协议元数据或等待文本本身不等于请求已经卡死；也不证明此前持续数分钟心跳的请求属于正常思考。
