# 全局提示词转发规则

管理员入口：**中转管理 → 提示词规则**（`/admin/relay`）。首次启动默认开启并填入提供的四条规则；之后启动保留管理员的修改与开关状态。

支持编辑、开启/关闭、填入默认规则、自动封禁阈值和撤销未保存修改。所有操作点击「保存设置」后生效，关闭时保留设置及历史记录，后续请求停止规则注入与拒答检测。启用时内容不能为空，最多 16000 个字符。封禁阈值默认 **3 次**，允许 **1–1000 的整数**，小数和字符串等非整数输入返回 400。

配置保存在 `relay_prompt_rule_config` 单行表，应用启动自动建表和初始化；旧表自动补充 `auto_ban_threshold` 列，已有规则内容和开关保留。管理员专用 `GET/PUT /api/admin/relay/prompt-rule-config`，返回 `Cache-Control: no-store`，设置字段为 `enabled`、`content`、`autoBanThreshold`。保存成功后当前后端实例的后续请求立即使用新设置；多实例部署时其他实例需重启以重新加载。

| 接口 | 注入位置 |
| --- | --- |
| Chat Completions | 第一条 `system` 消息 |
| Responses、Responses compact | `instructions` 前缀，保留原有 instructions |
| Anthropic Messages、count_tokens | `system` 内容块前缀，保留原有块与缓存标记 |
| Completions | `prompt` 前缀；批量文本逐项注入 |
| Images generations、edits | `prompt` 前缀，覆盖 JSON 与 multipart |
| 站内绘图、后台渠道测试 | 同一份全局配置 |

普通和流式转发、渠道重试均在构造上游请求时应用规则，保留原始请求，避免重试累加。客户端的系统提示、工具调用、图片及其他参数保留。规则增加的输入 Token 计入上游真实用量。

向量、审核和音频接口没有通用系统指令字段，保持输入原样，避免污染向量结果、审核数据或合成语音。Completions 的 token ID 数组无法安全合并文本规则，开启规则时返回 400，客户端可改用文本或文本数组。

这是提示词转发机制，实际模型行为和指令优先级仍由上游决定；单独附加规则无法保证阻止所有提示词攻击或泄露。

同页的「规则拒答命中」按用户汇总触发标记，展示「观察中／已封禁」、累计次数、首次/最近时间、最近接口、模型和脱敏的最新用户消息摘要。支持搜索用户名或用户 ID 和分页；管理员专用接口为 `GET /api/admin/relay/prompt-rule-config/hits`。状态来自账号当前的 `banned` 标志，管理员手动解除封禁后也会随之更新。

触发依据是规则开启时，模型的完整文本回复匹配「抱歉，该请求违反平台使用规范」（忽略空白与标点）。这是模型拒答证据，不是攻击定性；提到 jailbreak 等关键词、错误响应、工具输出或思考内容不直接触发。支持 Chat/Completions、Messages、Responses 普通和流式回复，流式按实际文本增量合并；每个请求只记一次，重试不重复累计。记录保存在 `relay_prompt_rule_hit`，重启保留，关闭规则后历史仍可查询。更改规则的拒答措辞后不匹配原句的回复不会被此检测器标记；不追溯历史日志，也不把无文本回复的绘图请求或后台渠道测试归属为用户触发。记录失败不会中断转发或计费。

拒答命中后，普通请求、流式请求及流式请求的 JSON 回退响应均返回真正的 **HTTP 400**，响应为 JSON，`error.code` 为 `security_policy_violation`，`error.message` 为：

> 当前触发系统安全策略限制，请立刻停止当前行为。当前账号已被标记观察，如果继续会自动封禁该账号。如有误判，请联系管理员。

命中日志记录状态码 400；上游已产生的用量仍按现有机制结算，不因转换为策略错误而免除或重复计费。拒答不会触发换渠道重试。

为在响应头提交前确定状态码，流式回复先检查可能的拒答前缀。单候选 Chat/Completions 和 Messages 一旦确认文本偏离拒答句，就继续逐段转发。Responses 可有多个 assistant 消息，且多候选回复可在后面的候选项中拒答，因此两者在规则开启时等待完整输出后再返回。只有收到成功终止事件才算命中；错误或中断不标记。缓存超过 64 KiB 时使用临时文件，完成或失败后清理；检测期间继续使用原有上游空闲超时保护。关闭规则恢复直接流式转发。

每个用户按 `relay_prompt_rule_hit` 的累计唯一请求数判断封禁，跨 API Key 累计，默认第 3 次命中封禁。插入记录、计数、封禁及注销登录会话在同一数据库事务内处理，并锁定用户行，避免多个实例并发命中漏掉阈值。达到阈值后设置账号 `banned = 1` 并递增 `auth_version`，现有网站和中转鉴权会限制该账号的后续访问。规则不区分用户角色。

修改阈值不追溯批量封禁历史用户，在下一次新命中时使用新阈值判断。管理员可在「用户管理」解除封禁；解除封禁不清空历史次数，之后再次命中仍按累计次数判断。记录或封禁事务失败时回滚并记录服务端告警，不将该存储异常暴露给客户端。

验证覆盖配置持久化及旧表迁移、默认第三次/自定义阈值封禁、跨实例并发、去重和事务回滚、普通与三种协议流式拒答的 HTTP 400、流式 JSON 回退、计费与并发资源释放、关闭规则、流式字节重放及临时文件清理、脱敏和管理员权限。前端类型检查和生产构建通过。浏览器使用模拟管理员接口验证阈值编辑/校验、保存回读、撤销、失败保留草稿、规则开关和状态展示；截图：[桌面](screenshots/relay-prompt-auto-ban-desktop.png)、[手机](screenshots/relay-prompt-auto-ban-mobile.png)。可使用 `scripts/verify-prompt-policy.cjs` 复验界面（需 Playwright、Chromium 及本地 Vite 服务；通过 `PLAYWRIGHT_MODULE`、`CHROMIUM_EXECUTABLE`、`FRONTEND_URL` 指定路径）。全量后端测试另有两项应用集成测试因本地未配置 `JWT_SECRET` 无法启动。
