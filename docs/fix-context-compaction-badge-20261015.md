# 普通接口上下文压缩标识

原实现只根据 `responses/compact` 路径显示「压缩」。现在普通 `/chat/completions`、`/responses`、`/messages` 也会根据当前请求中的常见上下文总结指令，或上游实际生成的 `compaction` 块识别压缩，并将结果保存到 `relay_usage_log.context_compaction`。

用户使用记录、近期调用、错误记录、管理员日志、管理员用户详情和用户 CSV 导出共用这个结果。标识提示说明上下文变化可能造成后续缓存命中下降。

识别检查最新用户指令及专用 system/developer 指令，不根据缓存未命中、gzip/zstd、开启自动压缩设置或历史压缩内容推断。流式、非流式、失败及日志兜底写入保留分类。

部署时需要同时更新前后端；后端启动的 `RelaySchemaInitializer` 会为已有表增加可空字段，新建表及手动升级 SQL 也已同步。历史记录继续通过 compact 端点兼容展示；普通端点历史日志未保存原请求，无法可靠补标。自定义压缩提示词若未匹配常见指令且上游不返回明确压缩块，可能仍无法识别。

验证：前端生产构建及 2 项标识测试通过；129 项后端测试通过，覆盖分类、流式/非流式落日志、失败记录、估算用量、兜底写入、DTO 透传及原计费行为。
