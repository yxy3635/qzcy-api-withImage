# 渠道多供应商 + 调度算法 设计方案

## 设计总览

引入两层调度,渠道变成"逻辑分组单元",供应商变成新的子实体:

```
请求 → 跨渠道调度(现状不变):priority 分层 + 层内加权随机
     → 渠道内调度(新增,按渠道配置的策略):对启用且健康的供应商排序
     → 现有 dispatch for 循环天然实现逐个 failover
```

- **渠道(relay_channel)** 保留:分组、模型绑定(渠道级共享)、跨渠道 priority/weight、RPM/TPM/并发限流、成本倍率、新增 `schedule_strategy`(调度策略)。
- **供应商(relay_channel_provider,新表)**:name、api_base_url、api_key、channel_rule(openai/anthropic)、priority、weight、status(健康)、enabled。
- 渠道旧的 base_url/api_key 字段保留不删:无供应商时兜底使用,保证兼容。

## 1. 数据库(schema.sql + RelaySchemaInitializer.java)

新表:
```sql
CREATE TABLE IF NOT EXISTS relay_channel_provider (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    channel_id BIGINT NOT NULL,
    name VARCHAR(80) NOT NULL DEFAULT '',
    api_base_url VARCHAR(255) NOT NULL DEFAULT '',
    api_key VARCHAR(255) NOT NULL DEFAULT '',
    channel_rule VARCHAR(40) NOT NULL DEFAULT 'openai',
    priority INT NOT NULL DEFAULT 10,
    weight INT NOT NULL DEFAULT 10,
    status VARCHAR(20) NOT NULL DEFAULT 'unknown',
    enabled TINYINT(1) NOT NULL DEFAULT 1,
    created_at DATETIME NOT NULL, updated_at DATETIME NOT NULL,
    INDEX idx_rcp_channel (channel_id)
);
```
`relay_channel` 加列 `schedule_strategy VARCHAR(20) NOT NULL DEFAULT 'weighted_random'`。

`RelaySchemaInitializer`(backend/.../config/RelaySchemaInitializer.java)新增:
- 建表 + 加列;
- **数据回填**:对没有供应商记录的渠道 `INSERT ... SELECT` 一条供应商(name 取渠道 provider 标签,base_url/api_key/rule 复制),老用户升级后行为不变。

## 2. 实体 / Mapper

- 新实体 `entity/RelayChannelProvider.java`(照 RelayChannel 风格)。
- 新 `mapper/RelayChannelProviderMapper.java`:`selectByChannelId`、`selectEnabledHealthyByChannelId`(enabled=1 AND status<>'failed' AND base_url/key 非空)。
- `RelayChannelMapper.selectDispatchCandidates`:去掉 `c.api_key/c.api_base_url` 非空条件(凭证在供应商上),其余 JOIN/分组过滤不变;无供应商且无旧凭证的渠道在 Java 侧跳过。

## 3. 调度器(核心新代码)—— 新类 `service/impl/RelayProviderScheduler.java`

```java
public List<RelayChannelProvider> order(RelayChannel channel, List<RelayChannelProvider> providers)
```
按 `channel.schedule_strategy` 分派四种算法(每个策略输出**完整有序列表**,交给现有 failover 循环):

1. **weighted_random(默认)**:供应商按 priority 分层,层内加权随机不放回洗牌(复用 RelayPolicyServiceImpl 的 weightedOrder/weightedPickOne,抽成共享逻辑)。
2. **smooth_rr 平滑加权轮询**:nginx 算法,`current_weight += weight`,选最大者并 `-= totalWeight`;状态存 `ConcurrentHashMap<channelId, Map<providerId, currentWeight>>`,管理员保存渠道时清空该渠道状态;选中者排第一,其余按 priority/weight 跟后。
3. **least_conn 最小并发**:`ConcurrentHashMap<providerId, AtomicInteger>` 在途请求计数(dispatch 尝试前 +1 / finally -1),按在途数升序、同数按 weight 加权随机。
4. **priority 严格故障转移**:priority ASC → weight DESC → id ASC 固定顺序,永远先打第一个。

调度器做成无依赖纯逻辑类,方便单测。

## 4. RelayContext 与 dispatch 改造

- `dto/relay/RelayContext.java` 增加 `RelayChannelProvider provider` 分量(可空)。
- `RelayDispatchServiceImpl`:
  - 新增 `endpointBaseUrl/endpointApiKey/endpointRule(context)`:provider 优先,渠道旧字段兜底;`upstreamRequest`/`upstreamMultipartRequest`/`applyAuthHeaders`/`isAnthropicChannel` 全部改走这些方法;日志增加 providerId/providerName。
  - 熔断 key 由 `channelId` 改为 `channelId + ":" + providerId`(无供应商时退化为 channelId),`CHANNEL_CIRCUITS` 改 `Map<String, ChannelCircuitState>`。
  - least_conn 计数器在每次上游尝试前后增减;流式并发闸门保持渠道级不动。

## 5. chooseChannels(RelayPolicyServiceImpl)

渠道排序逻辑不动;对每个渠道:取启用健康供应商 → `providerScheduler.order(...)` → 每个 (channel, provider) 生成一个 RelayContext(channelModel 绑定每渠道查一次复用);无供应商但旧字段齐全 → 合成"隐式供应商"兜底。

## 6. 管理 API(RelayServiceImpl / DTO)

- 新 `RelayProviderUpdateDto`(id 可选;apiKey 留空 = 不修改,返回用 mask() 打码)。
- `RelayChannelUpdateDto` 增加 `providers`、`scheduleStrategy`;`RelayChannelDto` 增加 `scheduleStrategy`、`List<RelayProviderDto> providers`。
- createChannel/updateChannel:校验至少 1 个供应商且 base_url/api_key 非空、rule 合法;按 id **diff 同步**(更新已有/插入新增/删除缺失);保存后清调度器 rr 状态。deleteChannel 级联删供应商。
- `fetchUpstreamModels`:遍历渠道所有 enabled 供应商拉 `/v1/models` 取**并集去重**(单个失败不阻塞,全失败才报错)。
- Controller 无需新增端点(供应商随渠道 payload 提交)。

## 7. 健康探测(RelayChannelStatusServiceImpl)

探测粒度改为供应商:逐个 enabled 供应商探测 `/v1/models` 写 `provider.status`;渠道 status 聚合(任一可用=available,全挂=failed,无供应商走旧字段兜底)。

- `src/types/index.ts`:新增 `RelayChannelProvider`,`RelayChannel` 增加 `scheduleStrategy`/`providers`;`src/api/adminApi.ts` 同步。
- `src/views/admin/AdminRelay.vue`:
  - 渠道弹窗:移除渠道级 供应商/Base URL/API Key/规则 四字段,替换为**供应商列表编辑区**——每个供应商一行卡片(名称、Base URL、API Key[编辑留空=不改,placeholder 显示打码值]、规则下拉、优先级、权重、启用开关、删除),"添加供应商"按钮;
  - 渠道级新增"调度策略"下拉(加权随机/平滑加权轮询/最小并发/严格优先级)+ 一句说明;
  - `ChannelDraft`/`newChannel`/`channelPayload()` 增加 providers 与 scheduleStrategy;
  - 渠道列表卡片:供应商 badge(名称 + 状态点)+ 策略标签;模型绑定区不动。
