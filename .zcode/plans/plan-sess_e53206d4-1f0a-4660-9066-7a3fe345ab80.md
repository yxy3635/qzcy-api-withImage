# 渠道「测试」功能:仪表盘渠道卡上真实对话调用测试

## 交互设计(总览页 → 渠道状态墙 → 每张渠道卡)

- 卡片按钮行从 [检测][编辑] 变为 **[检测][测试][编辑]**;
- 点「测试」弹窗(复用 RelayModal):
```
测试渠道 · 主渠道                                    ✕
渠道将按「加权随机」策略选择供应商发起一次真实请求
├─ 选择模型:   [下拉:该渠道已绑定的启用模型]
├─ 测试内容:   [textarea,默认"你好，请用一句话介绍你自己。"]
├─ [发送测试](loading 提示:请求中最长约 1 分钟)
└─ 结果区:
   ✅ 调用成功 · 1.8s
   供应商:OpenAI官方(OpenAI 规则)
   实际调用模型:gpt-4o-mini   ← 大字突出展示
   回复:我是……(pre-wrap 完整展示)
   ❌ 失败时:错误信息 + 按顺序每个供应商的失败原因列表
```

## 后端

1. **新端点** `POST /api/admin/relay/channels/{id}/test`(AdminController,放 status/sync 旁),body `{ modelId, prompt }`,返回 `RelayChannelTestResultDto`:
   `{ success, providerName, providerId, rule, model, upstreamModel, latencyMs, content, error, attempts[{providerName, error, latencyMs}] }`
2. **新服务** `RelayChannelTestService` + impl,流程:
   - 校验渠道存在、模型绑定存在(未绑定报 400);prompt 截断上限 4000 字符
   - 实际发送模型名 = 绑定的 `upstream_model`,留空则用模型公开名(与正式转发规则一致)
   - 供应商列表:启用健康供应商,无则老渠道旧凭证合成隐式供应商(同 chooseChannels 兜底口径)
   - **复用 RelayProviderScheduler.order() 按渠道策略排序**——"按规则请求渠道",失败自动切下一个,全部尝试后汇总
   - 每个供应商按规则发一次非流式请求(HttpClient,连接 10s/请求 60s):openai → `POST /v1/chat/completions {model, messages, stream:false}` Bearer 认证;anthropic → `POST /v1/messages {model, max_tokens:512, messages}` + x-api-key/anthropic-version;URL 拼接和鉴权头照 fetchUpstreamModelsForEndpoint 的既有模式
   - 回复提取:openai 取 `choices[0].message.content`(兼容块数组),anthropic 拼 `content[].text`
   - 成功返回首个成功结果 + 尝试过程;全失败返回 error + 每个 attempt 的失败原因
3. **单测**:回复提取(openai 文本/块数组、anthropic text 拼接)、未绑定模型校验、兜底供应商、调度顺序接入。

## 前端

1. `adminApi.ts` 加 `testRelayChannelChat(id, {modelId, prompt})`(axios 全局 timeout 10 分钟,无需覆盖);`types/index.ts` 加 `RelayChannelTestResult`。
2. 新组件 `admin/RelayChannelTestDialog.vue`(RelayModal 壳):模型下拉(必选,默认第一个)、prompt textarea、发送按钮 + loading、结果区(成功:供应商/规则/耗时/**实际调用模型大字**/回复;失败:错误 + attempts 明细)。
3. `RelayDashboardPanel.vue`:emits 加 `chatTest: [channelId]`,渠道卡按钮行加 **[测试]**。
4. `AdminRelay.vue`:挂载弹窗;弹窗的模型列表取 `overview` 中该渠道 `models` 里 `enabled` 的绑定(modelId/model/displayName/upstreamModel);@chat-test 打开弹窗;测试完成后刷新仪表盘(供应商状态可能变化)。

## 验证

- 后端:`mvnw test` 全量 + 新单测;
- 前端:`npm run build`;
- 手工路径:总览 → 渠道卡「测试」→ 选模型 → 发送 → 看回复/模型名/供应商;失败渠道验证 failover 明细。

## 实施顺序

① 后端 DTO + 服务 + 端点 + 单测 → ② 前端 API/类型/弹窗组件 → ③ 面板按钮 + AdminRelay 接线 → ④ 全量验证。
